# Diff: arXiv 2607.08147 — *Prismata: Confining Cross-Site Prompt Injection in Web Agents*

Diffed against: `notes/skillguard_notes.md` (the user's notes on the anchor, arXiv 2608.30041 / SkillGuard).
Source: full text of 2607.08147, 15 pages. Pages 13–15 are empty after reference removal; Appendix A (action space, cited p.3) and Appendix B (model snapshots, cited p.8) are referenced but absent from the extracted text.

## Skip

- **The premise that argument semantics alone cannot decide safety.** Notes line 7 records SkillGuard's position that "determining whether such influence is safe from the natural-language semantics of argument is unreliable." Prismata states the same premise for the web setting on p.10 ("the web agent's actions are contextually uninformative (e.g., `click(element=101)`)") and p.11 ("`click(id)` carries no security meaning in isolation"). Same argument, different substrate; no new claim for the note.
- **Enforcement as an interposed reference monitor.** Notes line 3 records SkillGuard's "inline reference monitor" mediating invocations. Prismata's "mechanical confinement" (p.4) is the same construct — deterministic code interposing on every action before it reaches the browser — so the mechanism class is already covered. What differs is *what* it mediates; see Read.
- **The least-privilege framing itself.** Notes line 8–9 cover capability restriction as the governing idea; Prismata's "contextual least privilege" (p.1–2) restates it without adding to the note's content.

## Read

- **§1 Introduction, the web entanglement problem (p.1–2).** New: a named obstacle that does not arise in SkillGuard's setting — the security meaning of an action lives in *site structure* that is itself entangled with attacker content, so the act of deriving a policy exposes the derivation to the attack. The notes' Skill Impact Graph presumes trustworthy skill summaries; this section argues that no such trustworthy description exists per-action on the web.
- **§1 XSP as an attack class (p.1).** New: the framing of indirect prompt injection on a benign site as the agent-side analogue of XSS, and the argument that XSS defenses do not transfer (payloads are natural language, sanitizers cannot split instructions from data, external content cannot be sandboxed out of the agent's context).
- **§1.1 Critical paths (p.2).** New: the root-to-element DOM path as the *only* input to a per-element scope decision, so injections off that path provably cannot influence the label. This is a different isolation primitive from the notes' graph reachability — it isolates the *decision input*, not the reachable state set.
- **§2.2 Biba parsing (p.4).** New: no-read-down / no-write-up applied to recursive DOM labeling — an element is labeled from itself and its ancestry only, children and siblings masked, the label locked before descending, and a structural cue causes the label to cascade to the whole subtree. The notes have no analogue of a labeling order chosen to precede exposure.
- **§2.2 Policy model with no DOM content (p.4).** New: the origin-class policy is derived from task text alone, so entire provenance classes can be pruned; the attacker cannot influence which classes are retained.
- **§2.3 Security cases and the composition rule (p.4–5).** New: `cap(e,task) = min(cap_gate, cap_biba)`, the definition of an injection-free label (Def. 2.1, p.4), and the three-case analysis (Table 1, p.4) with Case 3 as the sole residual. Compare against the notes' minimum-cut disconnection: here the guarantee is a *minimum over two independent labelers*, not a graph cut.
- **§2.4 Informal proof (p.5).** New: an enumeration-of-attacker-strategies argument rather than a reachability argument. Also new: the containment claim that any mislabel is confined to elements whose critical path contains the injection (p.5).
- **§3 Empirical foundations (p.5–6).** New in kind: the security argument is grounded in a measured corpus of real DOMs, not in a proof over a model. The notes record no empirical grounding step for SkillGuard's graph assumptions.
- **§4.2 Evaluation framework (p.6–7).** New: `attack.step()` / `attack.success()` and `run_defense` interfaces, plus `defense_harness()`, which replays a known-good trajectory to check whether the defense would have blocked each step — a lower-bound utility metric that isolates defense over-restriction from agent randomness.
- **§4.3.2 Allowed-element precision/recall/F1 (p.7–8).** New: comparing the *set of elements surviving enforcement* under model labels versus expert labels, with the explicit reading that low precision weakens security while low recall only costs utility.
- **§5.1.1 Validation study design (p.8).** New: replacing the model labeler with a human web-security expert while holding the rest of the stack fixed.
- **§6.1 Why CaMeL-style pre-planning does not lift (p.10–11).** New: tool-calling defenses inherit ground-truth argument semantics; web actions are data-dependent, so pre-planning cannot be transferred without first solving entanglement.
- **§6.1 Three-level rather than dual-LLM (p.11).** New: the argument that a strict quarantined/privileged split is insufficient for the web, and that an *intermediary* level of exposure to untrusted content (Biba parsing) is required.
- **§6.3 Integrity-vs-accuracy trade-off (p.11).** New: the explicit statement that Prismata gives up labeling accuracy (a model seeing parents *and* children would label better) to buy mechanical blocking of upward tampering.
- **§6.3 Why structural cues exist (p.11–12).** New: WCAG section headers, BEM/semantic-HTML wrapper conventions, and SEO incentives are named as the reasons the Case-2 precondition holds in practice.

## Disagreements

Between the paper and the notes:

- **What is being confined, and at what granularity.** Notes line 4: SkillGuard's inputs are "Skill Impact Graph, initial capability set, and a forbidden state B" — a pre-declared model of security-relevant states. Prismata p.11: "web browsing is a fundamentally open-ended interface, typically featuring multiple ways to do the same thing," and "every web browsing task is inherently data-dependent." The paper argues that a pre-declared transition model of the kind the notes describe cannot be constructed for its setting. This is a scope difference between the two settings, but the paper states it as a limit on the whole pre-planning family, which includes the notes' formulation.
- **Declared parameter constraints vs. derived labels.** Notes line 7: "SkillGuard defines explicit constraints for each skill parameter. Under these constraints, the steerability signature specifies the type and permitted value range of each parameter." Prismata p.2 takes the opposite position for its setting: "manually annotating untrusted regions or mapping site elements to semantic actions does not scale," and it advertises "no developer annotations" (p.1) as a design requirement. The two papers disagree on whether per-parameter declarations are a workable foundation.
- **Minimal-cost cut vs. minimum of two labels.** Notes line 9: SkillGuard "disconnect[s] all paths to forbidden states on the execution graph at a minimal cost," recomputed on a contamination event. Prismata never computes a cut; enforcement is static per observation, `cap(e) = min(cap_gate, cap_biba)` (p.4), reapplied at every agent action by re-capturing and re-filtering (p.4). There is no contamination-triggered recomputation.
- **Where residual risk is admitted.** The notes record no residual-risk term. Prismata explicitly concedes Case 3 (p.5) and states the label "may still be correct" there, i.e. it declines to claim a guarantee over the full input space.

In-paper inconsistencies (recorded, not resolved):

- **Sample size for the empirical study.** p.2 twice describes "1,500+ of the most visited sites" and "our 1,500+ website sample"; §3 (p.5) reports 2,832 domains from the Tranco top 10K.
- **Model names in Fig. 8 vs. the text.** The text on p.9 names "Gemini 3 Flash" (highest F1, 95.14%) and "GPT-5.4-mini" ("a strong balance between precision and recall"); the Fig. 8 axis (p.9) lists Gemini 3.1 Flash Lite, GPT-5 Nano, GPT-OSS 120B, Qwen3 8B, MiniMax M2.5, GPT-5.4 Nano — neither "Gemini 3 Flash" nor GPT-5.4-mini appears, and the figure lists two distinct nano models the text does not distinguish.
- **Section cross-references.** p.8 (§5 intro) cites "§5.4" for both the second and the third evaluation, where the second is §5.4 Utility and the third is also §5.4. p.8 (§4.4) attributes Biba parsing to "§2.3", but Biba parsing is described in §2.2; §2.3 is Prismata Security. p.11 (§6.3) cites "§5.4" for the cross-model comparison, which is §5.3.
- **Fig. 3 caption vs. §2.2 enforcement ordering.** §2.2 (p.4) presents "Enforcement" before "Mechanical confinement" as separate headed paragraphs that describe overlapping steps; the paper does not state whether these are two stages or one, while p.4 earlier says the DOM is processed "in three stages."
- **Cache-savings arithmetic.** p.10 text says caching avoids "$1.821 through KV reuse"; the Fig. 10 panel-D annotations that survived extraction are $2.023, $0.202, and $1.102. $2.023 − $0.202 = $1.821, so the text is consistent with a no-cache/cached pair, but the figure's own label for the $1.821 quantity does not appear in the extracted text.

## Reading order

Given that the target is the user's SkillGuard notes:

1. **§6.1, p.10–11** — the CaMeL and dual-LLM paragraphs. This is the paper's direct argument about why declared-semantics, pre-planning defenses (the family the notes describe) do not lift to the web. Read it first; it tells you whether the rest is a competitor or a neighbour.
2. **§1.1, p.2** — the critical-path insight, in three paragraphs. This is the paper's substitute for the notes' reachability formulation.
3. **§2.3–2.4, p.4–5** — Def. 2.1, Table 1, and the composition rule. Compare `min(cap_gate, cap_biba)` against the notes' minimum-cut, and Case 3 against the notes' silence on residual risk.
4. **§3, p.5–6** — the empirical foundations. This is the move the notes have no counterpart for: measuring whether the structural assumption holds on real pages before claiming the guarantee.
5. **§2.2 Biba parsing, p.4** — the labeling-order mechanism, once you know from step 3 that its precondition is empirically supported.
6. **§4.2–4.3, p.6–8** — `defense_harness()` and the allowed-element metrics, if the interest is in how to evaluate a confinement mechanism rather than in the mechanism.
7. **§6.3, p.11–12** — the integrity-vs-accuracy trade-off and the structural-cue conventions, last; useful for framing but not load-bearing.

Skip §4.1 (p.6) and §6.2 (p.11) unless the web setting itself is of interest; they are attack-template and XSS-background material with no bearing on the notes.
